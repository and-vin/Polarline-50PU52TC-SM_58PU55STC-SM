# План: Алиса → фильм на телевизоре

[English](alice-plan.en.md)

Цель: сказать Алисе на станции (например, «Алиса Мини») «посоветуй фильм», получить совет и командой «включи» открыть этот фильм на телевизоре в КиноПоиске, RUTUBE или VK Видео.

Статус: план, ничего не реализовано. Перед работой на ТВ прочитать [AGENTS.md](../AGENTS.md).

## Архитектура

```
Станция ──голос──▶ Яндекс Диалоги ──webhook──▶ облачная функция (навык)
                                                   │  поиск фильма (КиноПоиск API / RUTUBE)
                                                   ▼
                                             очередь команд
                                                   ▲  исходящее соединение (long-poll / WebSocket)
                                                   │
                                 служба на ТВ (APK, root) ──am start──▶ приложение
```

1. **Свой приватный навык Алисы** (например «Киновечер»). Весь разговор идёт внутри навыка: «посоветуй» → предложение фильма → «ещё» / «включи». Короткий вариант: «Алиса, попроси Киновечер включить Дюну».
2. **Облачная функция** (Yandex Cloud Functions или аналог): обрабатывает фразы, ищет фильм, кладёт команду в очередь.
3. **Служба на ТВ** — маленький APK (как `launcher/`, без AndroidX), сама держит исходящее соединение с облаком: проброс портов на роутере не нужен. Получив команду, будит экран и открывает фильм. На Android 7 запуск activity из фона разрешён (ограничение появилось в Android 10). Бюджет памяти — 10–15 МБ.
4. **Выбор приложения:** явно («на Рутубе») или по порядку КиноПоиск → RUTUBE → VK Видео. При нескольких кандидатах (фильм, трейлер, обзор) — список на экране ТВ, выбор голосом («второй») или пультом.

## Что выяснено

- **Контекст обычного разговора с Алисой не получить.** Сторонний навык не видит предыдущих реплик. [ha-yandex-station-intents](https://github.com/dext0r/ha-yandex-station-intents) реагирует только на заранее заданный список фраз (без подстановок). [YandexStation](https://github.com/AlexxIT/YandexStation): сказанную фразу узнать нельзя, текстовый ответ Алисы возвращается только для ограниченного набора (погода, время, умный дом). Поэтому совет должен давать сам навык.
- **Навык:** приватный навык проходит модерацию только имени активации и иконки. Имя — 2–5 слов, без «Яндекс», «Алиса», «Станция». Ответ навыка — за ~3 с, допускается не больше 1 ошибки сервера на 10 запросов ([требования](https://yandex.ru/dev/dialogs/alice/doc/ru/requirements)).
- **RUTUBE:** поиск сайта `GET https://rutube.ru/pangolin/api/web/v1/search/combined/video_playlist?query=<текст>&client=wdp&page=1` работает без авторизации, отдаёт `id` (32 hex), `title`, `duration` (с), `author.name`, `is_official`. Старый `/api/search/video/` возвращает пустой список. В выдаче много лишнего (трейлеры, музыка, фейки вроде «Интерстеллар 2 (2027)») — фильтр по длительности (≥ 60 мин) и автору, сомнительное — списком на экран.
- **КиноПоиск, поиск по названию:** неофициальный `kinopoiskapiunofficial.tech` (`/api/v2.1/films/search-by-keyword?keyword=`), нужен бесплатный ключ (`X-API-KEY`); без ключа `401`. Неофициальные API периодически ломаются. Проверено 28.10 с ключом: поиск находит фильм и отдаёт числовой kp-id (`Интерстеллар` → 258687), но отвечает 7–10 с — больше лимита навыка (~3 с), нужен кэш или поиск заранее. `/api/v2.2/films/<kp-id>/external_sources` перечисляет другие онлайн-кинотеатры, ссылки на КиноПоиск HD и HD id в нём нет.
- **VK Видео:** поиск через API VK требует пользовательского токена — скорее всего, только открытие экрана поиска в приложении.
- **Другие приложения:** только запуск или передача текста в их поиск, если они это принимают.
- **Риск:** VK Видео для Android TV 2.118 требует Android 9, на ТВ работает 2.22 — приложения на этой прошивке скоро нельзя будет обновлять, интеграции могут сломаться, когда сервисы перестанут поддерживать старые версии.

## Шаг 1: какие ссылки принимают приложения (на ТВ)

Какие ссылки (`VIEW` с `scheme/host/path`) и поисковые intent (`android.intent.action.SEARCH`, extra `query`) принимает каждое приложение, нигде не описано — проверяется только на ТВ.

PowerShell (VPN выключен):

```powershell
adb connect <IP ТВ>:5555
foreach ($p in 'ru.kinopoisk.tv','rtb.mobile.android','com.vk.tv') {
  "=== $p"
  adb shell "dumpsys package $p | grep -E 'Scheme|Authority|Path|Action:|android.intent.action.(VIEW|SEARCH)' | sort -u"
}
```

Затем пробные запуски, например:

```
adb shell am start -a android.intent.action.VIEW -d "https://rutube.ru/video/<id>/" rtb.mobile.android
adb shell am start -a android.intent.action.VIEW -d "https://www.kinopoisk.ru/film/258687/" ru.kinopoisk.tv
adb shell am start -a android.intent.action.SEARCH -e query "Интерстеллар" <пакет>
```

Итог — таблица «приложение → способ: ссылка на фильм / экран поиска с запросом / ввод нажатиями (`input text` под root, запасной вариант)».

### Результат (28.10.2026)

Проверено на КиноПоиске 2.262.1, RUTUBE 31.14.2.TV-google и VK Видео 2.22. Запрос в ссылке — в URL-кодировке (`%D0%98…`).

| Приложение | Ссылка на видео | Экран поиска с запросом | `SEARCH` + `query` |
|---|---|---|---|
| RUTUBE | работает: `rutube://rutube.ru/video/<id>/` → плеер | работает: `rutube://rutube.ru/search/?query=<запрос>` → результаты | не принимает |
| VK Видео | работает: `https://vk.com/video<owner>_<id>` → сразу воспроизведение | работает: `vkvideo://video/search?query=<запрос>` → результаты | фильтр есть, запрос игнорирует |
| КиноПоиск | работает только с HD id: `kpatv://film?filmId=<hd_id>` или `https://hd.kinopoisk.ru/film/<hd_id>` → карточка; как получить HD id по названию без входа — не выяснено | по ссылке не работает; работает ввод нажатиями (см. ниже) | фильтр есть, запрос игнорирует |

Рабочие команды:

```
adb shell am start -a android.intent.action.VIEW -d "rutube://rutube.ru/video/<id>/" rtb.mobile.android
adb shell am start -a android.intent.action.VIEW -d "'rutube://rutube.ru/search/?query=<запрос>'" rtb.mobile.android
adb shell am start -a android.intent.action.VIEW -d "https://vk.com/video<owner>_<id>" com.vk.tv
adb shell am start -a android.intent.action.VIEW -d "'vkvideo://video/search?query=<запрос>'" com.vk.tv
adb shell am start -a android.intent.action.VIEW -d "'kpatv://film?filmId=<hd_id>'" ru.kinopoisk.tv
```

Подробности:

- **RUTUBE:** `https://rutube.ru/...` приложение не принимает (`unable to resolve Intent`), только схему `rutube://rutube.ru` (`ru.rutube.app.SplashActivity`). Ролики 18+ сначала спрашивают «Вам уже есть 18 лет?», по умолчанию выбрано «Нет».
- **VK Видео:** все ссылки принимает `com.vk.tv/.presentation.base.links.TvLinkRedirectActivity` (`https://vk.com/video.*`, `vkvideo://video|vk.com/.*`). У этой activity есть фильтр `SEARCH`, но без категории `DEFAULT`: без `-n` intent не находится, а с `-n` приложение открывает главную. Холодный старт — около 30 с.
- **КиноПоиск, ссылка на фильм:** id КиноПоиск HD — 32 hex (например `07e9b11ab8574bd3a863184ad89fd72e`), это не id с kinopoisk.ru. С числовым id (`258687`, `43395`) карточка открывается с ошибкой «Сервер недоступен». Формат нашёлся в `/data/data/ru.kinopoisk.tv/databases/YandexPlayer.db` (root, только чтение): приложение кладёт в рекомендации Android TV ссылки `kpatv://film/?filmId=<hd_id>&utm_source=androidtv&utm_medium=channels` (base64 дважды). Обе ссылки — `kpatv://film?filmId=<hd_id>` и `https://hd.kinopoisk.ru/film/<hd_id>` — открывают `HdContentCardActivity` с карточкой примерно за 6 с, когда приложение уже запущено. `https://www.kinopoisk.ru/film/...` не принимается. Публичного запроса «название или kp-id → HD id» без входа не нашлось.
- **КиноПоиск, поиск:** ссылками не открывается. В приложении есть обработчик `kpatv://home` с параметром `search_query`, но `kpatv://home/search?search_query=…` и `kpatv://home?page=search&search_query=…` открывают главную. SEARCH без `-n` не находится; `.splash.impl.presentation.SplashScreenActivity` отключена, `DeepLinkTargetActivity` открывает главную. Работает ввод нажатиями, root не нужен:

  ```
  adb shell am start -n ru.kinopoisk.tv/.presentation.splash.SplashActivity   # до главной ~15 с
  # если открылось «Выберите аккаунт» (SelectFamilyAccountActivity): adb shell input keyevent 23
  adb shell input keyevent 21   # влево, в боковое меню
  adb shell input keyevent 19   # вверх, на «Поиск»
  adb shell input keyevent 23   # OK, открывается экран поиска с курсором в строке
  adb shell input text Interstellar   # результаты через ~5–8 с
  ```

  `input text` вводит только ASCII, для кириллицы нужен другой способ (например, IME-приложение или ввод латиницей). Последовательность клавиш зависит от того, где стоит фокус на главной; службе надёжнее проверять `mCurrentFocus` после каждого шага.
- **КиноПоиск, выбор аккаунта:** при холодном старте и по многим ссылкам КиноПоиск показывает «Выберите аккаунт» (семейный аккаунт). После `input keyevent 23` ссылка на фильм сохраняется, ссылка на поиск теряется.
- **Память:** при пробах система разом выгрузила КиноПоиск, RUTUBE, лаунчер и сервисы Google (`am_proc_died`). Перед открытием ссылки службе стоит закрывать другие видеоприложения.

## Шаг 3: модуль поиска фильма

`alice/search.py` — только стандартная библиотека Python, подойдёт для Yandex Cloud Functions. `search("<название>")` возвращает данные КиноПоиска (если есть) и список команд для службы на ТВ в формате шага 1: ролики RUTUBE (`open`), затем поиск в КиноПоиске (`search_keys`, ввод нажатиями) и в VK Видео (`search`). Ключ КиноПоиска — в переменной окружения `KINOPOISK_API_KEY`.

- RUTUBE ищется двумя запросами параллельно («<название>» и «<название> фильм» или «<название> <год>»). Отсев: длительность ≥ 60 мин (для сериала ≥ 18 мин), платные и трансляции, категории вне «Фильмы/Сериалы/…», трейлеры, обзоры, музыка, нарезки, «сиквелы» вроде «Интерстеллар 2», ролики, где название — часть другого («Остров сокровищ» на «Остров»). С данными КиноПоиска отбрасываются ролики с другим годом в названии или длительностью дальше 30 мин от фильма.
- КиноПоиск отвечает 7–10 с, поэтому идёт в фоне и кэшируется: на первый запрос по названию его данных нет, на повторный — есть.
- Проверка: `KINOPOISK_API_KEY=… python3 alice/check_search.py` (12 названий, отечественные и сериалы). Ответ 0,9–1,6 с. RUTUBE нашёл полный фильм для 7 из 12: Интерстеллар, Иван Васильевич меняет профессию, Москва слезам не верит, Т-34, Кин-дза-дза!, Остров (Лунгин). Не нашёл: Брат 2, Дюна, Начало (2010), Холоп, Ликвидация, Игра престолов — для них остаются поиск в КиноПоиске и VK Видео.

## Дальнейшие шаги

- **ТВ в режиме сна недоступен по сети (бэклог).** Кнопка питания переводит ТВ в suspend-to-RAM (`ro.CVTE_EN_STR=1`): засыпает весь SoC вместе с Wi‑Fi, хотя `wifi_sleep_policy=2`. ТВ не отвечает ни на ping, ни на adb, и служба на ТВ не получит команду. Варианты: Wake-on-WLAN — в прошивке есть `MtkTvNetwork.setWifiWolCtl(boolean)`/`getWifiWolCtl()`, будить ТВ magic-пакетом из локальной сети, например с роутера или станции; запрет suspend (wakelock под root) — ТВ будет потреблять больше в режиме ожидания; переключатель «STR» в настройках ТВ — при выключении STR ТВ полностью выключается, сеть тоже пропадает. Проверить, что реально работает на этой прошивке.

2. Служба на ТВ: APK с исходящим соединением, командами `open(app, ref)` / `search(app, query)` / `show_list(items)`, автозапуском после загрузки; замер RAM.
3. Облачная функция + очередь; приватный навык в консоли Яндекс Диалогов, сценарии «посоветуй / ещё / включи / на <приложении>».
4. Подбор фильмов по вкусам владельца.
5. Проверка голосом со станции целиком; описать в `README.md`, `README.en.md` и `AGENTS.md`.
